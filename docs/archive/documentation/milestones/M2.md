# M2 — Host Service Runtime

Status: Complete on macOS arm64, with physical ESP32 M1 regression validation.

## Implemented

- `kernel/src/runtime` owns explicit Loaded → Initializing → Starting → Running → Stopping → Stopped/Failed transitions, admission, ownership, and diagnostics.
- `hal/include/micros/platform.h` separates task/synchronization/time/native-loading and simulated GPIO primitives from the manager. The POSIX implementation is in `platforms/host/src/platform.c`.
- Each loaded image has independent native globals/BSS, a zeroed arena, one joinable worker, an admitted stack and a fixed handle quota. A separate supervisor detects overdue hooks even if the controller stops polling.
- Timer callbacks and lifecycle hooks execute serially on the worker. Timers may be one-shot or periodic; missed periodic occurrences coalesce. Callbacks return a service result and are covered by the work deadline.
- Simulated digital lines are exclusive, readable/writable, and reset on release. Owner, generation, and resource type are checked on every handle use. Generation exhaustion retires slots instead of wrapping.
- Failed init/start/step/callback/stop enters cleanup. Stop suppresses new work and resource acquisition, waits for active work, runs the stop hook, releases remaining owned resources, and joins before unload.
- A timeout poisons the entire runtime with `MICROS_ERROR_REBOOT_REQUIRED`. Image, arena, stack, handles, and task remain owned. Unload, new load, and destruction are rejected. The command-line process reports the failure and exits with status 2; it does not cancel the worker or reclaim live native code.

## API and lifecycle decisions

Experimental ABI 0 revision **2** appends timer and simulated-GPIO callbacks to the kernel API table. Descriptor layout and image-envelope format remain unchanged; exact revision matching rejects revision-1 images. Both M1 harnesses implement explicit unsupported-resource stubs. Rebuild firmware and services together after this ABI change.

Management calls use a single controller thread. Worker SDK calls and the independent deadline supervisor are synchronized. Start is asynchronous. Stop on Loaded is a no-op; stop on Stopped is idempotent. A stale instance identity is rejected even after unload, so an old stop request cannot affect a replacement. Restart is unload, fresh load, and start; terminal instances cannot be started in place.

The manager retains image/arena/stack reservations until unload. Owned resource handles are released after cooperative cleanup, including when the service's own stop hook returns an error. Joining is still required before unloading a Failed instance. The first hook error is preserved; a timeout takes precedence and requires whole-process recovery.

## Bounded host profile

| Resource | Default policy | Rationale |
| --- | --- | --- |
| Loaded services | 4 | M3 graph plus test/management headroom |
| Handles | 8 per service, 32 total | Small fixed timer/GPIO ownership tables |
| Simulated GPIO | 4 exclusive lines | Minimal bounded host hardware fixture |
| Arena | Up to 4 KiB per descriptor; 16 KiB aggregate | Retain the M1 per-service admission ceiling |
| Requested stack | 4–16 KiB per descriptor; 64 KiB aggregate | Retain the M1 prototype range |
| Actual host stack | 64 KiB floor per service; 256 KiB aggregate | POSIX/libc overhead; accounted separately |
| Supervisor stack | 64 KiB | Kernel overhead, outside service reservations |
| Image payloads | 4 MiB envelope cap per load; 16 MiB aggregate payload ceiling | Defensive file/allocation bound inherited from M1 |
| Init/start/stop deadline | 1 second each | Initial failure-detection policy |
| Step/callback deadline | 10 ms each | Bounded unit of native work |
| Step interval | 1 ms | Avoid busy looping while timer deadlines also wake the worker |

The sample runtime service requests a 24-byte arena and a 4 KiB stack; the host reserves 64 KiB for that worker. On this build, the runtime/BSP/supervisor wrapper metadata is 3,076 bytes before a service worker is created. Metadata includes the fixed service and resource tables. Diagnostics separately report arena padding, live task wrappers, requested/actual stacks, payload bytes, reserved/live handles, and active callbacks.

Native Mach-O mapping sizes, dyld internals, pthread internals, guard pages, and allocator bookkeeping are host OS overhead, not measured physical RAM usage. The transient image read is capped at one envelope per single-controller load. Service-visible quotas remain enforced. Trusted native code can still corrupt memory or call unsupported native imports; these are ownership/admission contracts, not process isolation.

## Validation

Run the standard host build and CTest commands in [BUILDING](../BUILDING.md). Seven CTest entries cover:

- Twenty independent reloads, restored globals/BSS/arena, valid/invalid state transitions, and return to the tracked-resource baseline.
- Independent concurrent services; unloading one leaves its peer running.
- Separate image, arena, requested-stack, host-stack and handle admission failures; full service-table rejection.
- Handle exhaustion, double-close, cross-owner use, wrong resource type, GPIO conflicts, stale instance identities, and forced generation exhaustion.
- Failed init/start/step/stop/callback cleanup; stop during init/start and while a timer callback is active.
- Hung init/start/step/stop/callback in subprocesses, proving retained ownership and the recovery-required outcome. The init case verifies detection without controller polling.
- Existing M1 independent-image tests and twelve malformed/incompatible host-image cases, including the previous ABI revision.

The kernel/BSP/tests also pass AddressSanitizer and UndefinedBehaviorSanitizer. Independent service fixtures remain freestanding because sanitizer constructors/imports violate their native profile. Evidence is under [evidence/m2](evidence/m2).

Physical ESP32 validation flashed the revision-2 M1 firmware, loaded independently built v1/v2 services, ran four clean cycles, rejected eleven malformed images plus empty RUN, and returned heap to 226,076 bytes. Service measurements remain 280 code / 148 data / 4 BSS bytes, arena 16 bytes, stack 4,096 bytes. M2 does not claim that the full manager or timers run on the MCU; that is M5.
