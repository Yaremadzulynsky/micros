# M4 — Packages, Admission, and Local Management

Status: Complete for the host profile. Full ESP32 runtime integration follows in M5.

## Package and admission contract

Format-1 `.msp` files are deterministic, uncompressed ZIP containers with exactly `manifest.json`, `image.mimg`, and declared `schemas/<identifier>.proto` members. No archive is extracted into arbitrary paths. Duplicate/unexpected members, compression, encryption, oversized records, incompatible ABI/target, bad lengths/checksums/hashes, malformed manifests, and undeclared schemas are rejected.

Manifests identify immutable name/version pairs, native target and ABI, image SHA-256, arena size/alignment, requested stack, handle/timer/GPIO capabilities, channel endpoints, schema identities, and declared interface compatibility. Service persistent-data version must be zero; no migration contract is accepted in v1. The native runtime independently checks descriptor memory requirements against the manifest before any graph hook runs.

Schema identity is SHA-256 of UTF-8 text normalized to LF, stripped line tails, and one final newline. Compatibility is a separate declared interface name/major and inclusive producer-minor acceptance range. A different hash is not automatically incompatible; a matching hash does not bypass resource/target checks.

Planning sorts services and channels deterministically, checks the complete enabled graph before mutation/execution, rejects exclusive GPIO conflicts, requires a publisher for every subscribed channel, and checks layouts/interfaces and separate resource classes. The host profile admits four loaded services, eight handles each, four channels of up to eight 256-byte payload slots, and M2 arena/stack/image ceilings. GPIO and channel permissions and a separate timer ceiling are enforced on the native SDK path, not merely trusted from the planner.

## Persistent store and CLI

Installed packages are content-addressed and immutable. Up to 64 packages and 64 MiB of package blobs may be installed; the enabled selection independently chooses at most four resident services. The generated native-image cache contains only the admitted graph (at most 16 MiB). Diagnostics rotate between two 1 MiB files; returned log tails are capped at 32 KiB. Metadata is separately bounded at 128 KiB per record. These are development host storage classes, not an ESP32 partition layout.

Package/index/selection updates use same-directory temporary writes, file synchronization, replace, and directory synchronization. Invalid selection changes preserve the current selection. M4 does **not** claim a completed power-loss activation guarantee; boot health, rollback, and interruption testing belong to M6.

`tools/cli/microsctl.py` implements package, inspect, install, list, plan, configure, enable, disable, boot, status, logs, start, stop, restart, and shutdown. A private user-owned Unix socket connects commands to one persistent controller and native runtime. Management is serialized; service diagnostics have a separate pipe with bounded rotation. The controller admits and checks every image before launching any hook, then initializes subscribers before publishers.

Stop unloads one resident service without removing it from the next-boot selection. Restart performs fresh load/init. Shutdown and boot reconstruct the same selected graph. Selection changes require a stopped runtime in M4. Losing the controller or an unrecoverable native timeout recovers the whole native process; no live service is reclaimed individually.

The local protocol has no kernel/firmware write operation. Network authentication and remote service management follow in M7.

## Validation

Thirteen host CTest entries pass, also with kernel/BSP/codec AddressSanitizer and UndefinedBehaviorSanitizer. New checks cover:

- Deterministic package bytes and admission output; malformed/oversized/duplicate archives, invalid JSON/manifest types and limits, target/ABI/hash rejection.
- Interface compatibility versus schema identity, missing publishers, conflicting layouts, capacity, and rejected configuration preserving the prior selection.
- Seven installed packages with three enabled; immutable version conflicts and stored-package corruption.
- Public CLI install/configure/boot/status/logs/start/stop/restart/shutdown, a second boot restoring the selection, and derived-cache repair/pruning.
- Native descriptor mismatch rejected before any service hook runs; undeclared IPC access rejected by the kernel; timer/GPIO policy limits tested directly.

The measured three-service plan reserves 96 arena bytes, 12,288 requested stack bytes, 196,608 host stack bytes, four handles, and 512 channel payload bytes. See [evidence/m4](evidence/m4) and the [build/CLI instructions](../BUILDING.md).
